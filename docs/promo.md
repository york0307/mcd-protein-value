## 1. V2EX（技术社区，讲工程）

标题建议：`用麦当劳官方 MCP 算了笔账：巨无霸和双层吉士汉堡的蛋白质一模一样`

正文：

麦当劳最近开放了官方 MCP（mcp.mcd.cn），我拿它做了个小东西，顺手发现了一件挺反直觉的事。

**巨无霸 ¥26.5 和双层吉士汉堡 ¥23，蛋白质都是 27g。**

贵的那款多花 ¥3.5，多摄入 300 多大卡 —— 多花的钱买的不是蛋白质。

这件事有意思的地方在于：麦当劳官方的营养表**没有价格**，门店菜单**没有营养成分**。
这两个数据分开看都发现不了上面那句话，只有把两份数据 join 起来才能算出来。
而价格还随门店和时段浮动，静态抓一次就过期，所以非用 MCP 不可。

做出来两个东西：

- **价格错觉对比器**（纯前端，不用注册不用 Token，选两款直接看结论）
  https://york0307.github.io/mcd-protein-value/
  默认那对是「薄皮焦香V翅 ¥16 vs 麦香鱼 ¥22」——贵的那款蛋白质反而少 1g
- **完整榜单报告**（20 款餐品的四项指标 + 红黑榜）
  https://york0307.github.io/mcd-protein-value/report.html

踩到的坑，比结论更值得记：

1. 响应是 Markdown 包裹 + 内嵌 JSON，按普通 JSON 解析会得到 0 条
2. `list-nutrition-foods` 的 data 是自定义表格文本（`[160]{...}:` + CSV），不是数组
3. `query-meals` 必传 storeCode/orderType/beType，裸调 400
4. 模糊匹配会错价：「吉士汉堡包」会命中「吉士汉堡包**套餐**」的套餐价 → 改成双向唯一匹配，宁可少收录
5. 极低热量饮品靠分母霸榜：13kcal 的浓缩咖啡蛋白密度 7.7 → 设了蛋白 ≥5g 门槛

源码：https://github.com/york0307/mcd-protein-value
数据是麦当劳南京新百餐厅的真实实时数据，换门店重跑即更新。

顺带一提，这是麦当劳程序员创意开发大赛的参赛作品，排名只看 Star 数，觉得有意思的话给个 Star 就是投票了。
