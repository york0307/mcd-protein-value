### 正文（可直接粘贴，约 520 字）

麦当劳开放了官方 MCP（mcp.mcd.cn），我拿它做了个小东西，先说结论：

**巨无霸 ¥27（513kcal / 蛋白 27g）和双层吉士汉堡 ¥23（429kcal / 蛋白 27g），蛋白质一模一样。**
贵的那款多花 ¥4，多摄入 84 大卡 —— 多花的钱买的不是蛋白质。

还有一对更反直觉的：薄皮焦香V翅 ¥16（17g）和麦香鱼 ¥22（16g），
**贵的那款多花 ¥6，蛋白质反而少 1g**，热量还多 133 大卡。

这件事单看任何一份数据都发现不了：官方营养表**没有价格**，门店菜单**没有营养成分**。
只有把两份数据按餐品 join 起来才能算出来。而价格随门店和时段浮动，静态抓一次就过期，
所以非用 MCP 不可。

做出来两个东西：

- **价格错觉对比器**（纯前端单文件，不用注册不用 Token，选两款直接看结论）
  https://york0307.github.io/mcd-protein-value/
- **完整榜单报告**（20 款 × 四项指标 + 红黑榜 + 品类图例）
  https://york0307.github.io/mcd-protein-value/report.html

比结论更值得记的是踩到的坑：

1. 响应是 Markdown 说明 + 内嵌 JSON，按普通 JSON 解析会得到 0 条，得先找 `## Original Response` 再 raw_decode
2. `list-nutrition-foods` 的 `data` 不是数组，是自定义表格文本：`[160]{productName,...}:` 后跟 CSV 行
3. `query-meals` 必传 `storeCode` / `orderType` / `beType`，裸调 400
4. 模糊匹配会错价：「吉士汉堡包」会命中「吉士汉堡包**套餐**」的套餐价 → 改成双向唯一匹配，宁可少收录也不错配
5. 极低热量饮品靠分母霸榜：13kcal 的浓缩咖啡蛋白密度 7.7 → 设了蛋白 ≥5g 准入门槛
6. 同一个数字在三处渲染出两个值：Python `%.0f` 是银行家舍入（26.5→26），JS `Math.round` 是半进位（→27），
   20 款里 7 款是 `.5` 价全中。在一份讲数据的榜单里「巨无霸 ¥26」和「¥27」同时出现会被当成数据错误
   → 舍入规则抽成单点定义，三处渲染共用
7. 菜单随时段变：早上拉只有 83 款（早餐），午市才有 124 款 → 线上产物用快照重放锁口径

**样本量口径先交代清楚**：营养库 160 款、门店单品 81 款（已排除 43 款套餐与周边），
名称精确匹配后得 20 款。20 款里 19 款是名称完全一致的精确匹配，
1 款是规格推定（营养库「麦辣鸡翅-2块」对菜单「麦辣鸡翅」，麦当劳麦辣鸡翅单份即 2 块），
这一款在页面上打了「规格推定」标记，不藏着。未匹配的多为当前时段未供应或限定款。
宁可少收录，也不错配 —— 公开榜单里错价的代价远高于少几款。

数据是麦当劳南京新百餐厅 2026-10-09 午市的真实快照，采集时间与页面生成时间在页面上分开标注。

源码：https://github.com/york0307/mcd-protein-value
纯 Python + 自包含 HTML，无外部依赖，clone 下来配好 Token 就能重跑，换城市即换榜单。
